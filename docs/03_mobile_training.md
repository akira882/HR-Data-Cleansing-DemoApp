# スマホで鍛える ― 判断ドリルとPC練習の組み合わせ方

> PCでまとまった時間を取れない人が、スマホで人事データクレンジングの **本質的な仕事** を鍛えるための設計と使い方です。
> 練習ページ：`mobile/hr_judgment_drill.html`（`python tools/build_mobile_drill.py` で作り直せます）

---

## 1. 結論：スマホでできること・できないこと

| 仕事の要素 | スマホ | 理由 |
|---|---|---|
| **判断**（同じ人か／報告すべき差異か／次に何をするか） | ◎ むしろ向いている | 1件30秒で完結し、毎日少しずつ繰り返すほど身につく |
| 原則の理解（推測で埋めない、誤統合が最悪 など） | ◎ | 状況問題で、知識ではなく判断として使う練習ができる |
| データを眺める・数える | ○ | Excelブックをスマホのアプリで開けば、フィルタや並べ替えはできる |
| 仕組みを作る（Python・テスト・再実行） | △ | 長いコードを書き、1,000行を何度も回す作業は、画面とキーボードの制約が大きい |

**スマホだけでプロになることはできません。** 最後に必要な「再実行できる仕組み」と「ポートフォリオ」は、PC（またはClaudeに書かせたコードを自分で検証する作業）が必要だからです。

**ただし、スマホのほうが優れている部分があります。** 人事データアナリストの価値の中心は判断で、コードは判断を毎月同じ品質で回すための道具です（[第0章](00_hr_data_analyst_training_program.md) X5 の主張）。判断の熟達には、少しずつ・毎日・答え合わせ付きで繰り返すことが効きます（X2の主張）。この条件は、週末にPCの前で2時間まとめてやるより、スマホで毎日5分やるほうが満たしやすいのです。

> **スマホで判断を鍛え、PCで仕組みを作る。両者は同じ汚れのパターンを扱うので、片方で学んだことがもう片方でそのまま効く。**

## 2. 判断ドリルの設計 ― 何をどう鍛えるか

### 2-1. 4種類の問題

| 種類 | 問われること | 実務での場面 | 問題の作り方 |
|---|---|---|---|
| **名寄せ** | Bのこのアカウントは、Aのどの社員か | 突合の第一歩。誤ると他人の情報が混ざる | 生成器のデータから自動作成（同姓同名・再雇用・ゼロ落ち・社員番号空欄・テスト用ID など） |
| **差異の判定** | この組で、報告すべき差異はどれか | 表記ゆれ（吸収する）と本物の差異（報告する）を見分ける | 生成器の正解表から自動作成。**約半分は「報告なし」が正解** |
| **次の一手** | この差異に、誰が何をすべきか | 是正依頼・エスカレーション・職務分掌 | 汚れの種類ごとに、実務の選択肢を手書き |
| **原則** | この状況でどう判断するか | 推測で埋めない、外れ値、空欄の意味、基準日 など | 9つの原則に対応する状況問題を手書き |

問題は全130問で、PCの練習データと同じ生成器から作っています。スマホで「ゼロ落ちは同一人物」と覚えたことは、PCで `zfill(6)` を書くときにそのまま使えます。

### 2-2. クイズアプリにしないための4つの工夫

ありがちなクイズアプリは「答えを覚えるゲーム」に落ちます。それを防ぐために、次の4つを組み込んでいます。

**① 半分は「何もしない」が正解**
実際のデータの大半は問題がありません。問題のある組ばかり出すと、何でも疑う癖がつき、実務ではノイズ（報告不要な差異）を大量に出す人になります。差異判定の約半分は「報告する差異はない」が正解です。

**② 答える前に「自信あり／迷った」を選ぶ**
実務で一番危ないのは、**自信を持って間違える** ことです。迷った判断は、実務なら誰かに確認するので事故になりません。ホーム画面には「自信ありで間違えた件数」を表示し、これを減らすことを目標にします。

**③ 解説は必ず原則につながる**
すべての解説の最後に、9つの原則（P1〜P9）のどれに関わるかを示します。原則タブでは原則ごとの正答率が見えるので、「P5（誤統合）が弱い」のように、弱点を原則の単位で把握できます。

**④ 間違いは消えずに戻ってくる**
間違えた問題は翌日、正解した問題は1→3→7→14→30日後に出し直します（間隔反復）。迷った問題・間違えた問題は「記録」タブに残り、**判断台帳（`learning/decision_ledger.csv`）に貼れる形式** でコピーできます。スマホの判断がPCの記録につながります。

## 3. 使い方

### 3-1. 開き方
- 公開済みのページをスマホのブラウザで開く（ブックマークかホーム画面に追加しておく）
- または、PCで `python tools/build_mobile_drill.py` を実行し、`mobile/hr_judgment_drill.html` をスマホに送って開く

記録（正答率・復習予定）は **その端末のブラウザにだけ** 保存されます。端末やブラウザを変えると引き継がれません。

### 3-2. 1日の使い方（5分）
1. 「10問はじめる」（時間がなければ「3問だけ」）
2. 選んでから、**自信ありか迷ったかを正直に選んで** 判定する
3. 印（確認済／差戻）と解説を読む。分からない言葉は「仕様書」タブで確認する

### 3-3. 1週間のリズム

| 曜日 | スマホ（5分） | PC（週末にまとめて） |
|---|---|---|
| 月〜金 | 判断ドリル10問 | — |
| 土 | 判断ドリル＋「記録」タブをコピー | 判断台帳に貼り、PCの練習（[第2章](02_how_to_train.md) の90分ループ）を1〜2回 |
| 日 | 原則タブで弱い原則を確認 | `weekly_log.md` に、スマホの弱点とPCの採点結果を並べて書く |

> 💡 スマホで何度も間違える種類は、PCでは **自分のコードで見逃している種類** であることが多いです。週末のPC練習のテーマは、スマホの弱点から選んでください。

## 4. PCの時間がほとんど取れない週の代わり：Claudeに書かせて、自分は判断と検証をする

PCを開けない週でも、スマホのClaudeアプリから、このリポジトリの作業をClaudeに依頼できます。

- 例：「`learning/starter_recon.py` を、氏名の空白ゆれを吸収するように直して、採点結果を見せて」
- **あなたの役割は、仕様を決めることと、結果を検証すること** です。これは実務のアナリストが外部の開発者や同僚に依頼するときの仕事そのものです

ただし、次の2つを守らないと学習になりません。

1. **直した理由を、あなたが説明できるまで聞く**（「なぜ `zfill(6)` なのか」「誤統合のリスクは増えないか」）
2. **採点ツールで客観的に確かめる**（「良さそう」ではなく、誤統合0件・再現率・ノイズの数字で判断する）

自分で書くのは、時間が取れる週に回せば十分です。

## 5. スプレッドシートでの練習（PC・タブレット）

Excel / Googleスプレッドシートで練習するためのブックも作れます。

```bash
python tools/generate_ab_sample_data.py --level 1 --seed 42 --xlsx
# → data/ab/training_workbook.xlsx
```

| シート | 中身 |
|---|---|
| `README` | 進め方 |
| `関数ドリル` | 使う関数を1つずつ練習する18問。G列に数式を書くと、H列に ○ か × が出る |
| `手順` | A_work・B_work の列ごとの目的・数式・構文の読み方・注意と、提出シートの作り方 |
| `A_raw` / `B_raw` / `org_raw` | 受領データ。全セルが文字列で、シート保護がかかっている（原本は書き換えない） |
| `A_work` / `B_work` | 原本の写し＋黄色の作業列 |
| `map_dept` / `map_type` | 変換表（自分で作る） |
| `matches` / `diffs` | 提出用。`item`・`cause` はプルダウンで選ぶ |

数式の構文の読み方は [第4章 スプレッドシート数式ガイド](04_spreadsheet_formula_guide.md) で、1列ずつ解説しています。

採点はブックのまま行えます。
```bash
python tools/score_recon.py --xlsx data/ab/training_workbook.xlsx --log
```

Googleスプレッドシートで使う場合は、ブックをGoogleドライブに置いて開きます。スマホのアプリでもデータを眺めたりフィルタをかけたりできますが、数式を書く作業はタブレット以上の画面をおすすめします。
